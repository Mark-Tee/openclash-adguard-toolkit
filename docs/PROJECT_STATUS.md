# 项目交接与验证状态

更新：2026-11-02。本文仅提炼项目决策与待办，不收录聊天原文、凭据、人员或真实工单。历史完成描述不等于当前运行状态。

## 已提炼的排障顺序
1. 先检查实际 DNS 链路、解析结果、命中规则和代理出口，再修改配置。
2. Steam 商店、社区、CDN 和游戏连接分别验证，单个 HTTP 成功不代表整套服务正常。
3. 订阅说明文字不能作为可用节点；候选配置应排除伪节点并检查有效代理。
4. Tailscale 的子网访问、出口节点和 DNS 接管分别核查，不以启用远程访问为由自动接管全局流量。
5. 候选、校验、备份、应用、回滚各步骤保留边界，不修改网络、DHCP、防火墙或 Wi-Fi 配置。

## 验证限制与改进建议
历史节点和性能结果仅适用于当时环境。后续优先增加离线候选配置回归测试与跨平台脚本语法检查；生产路由器的改动需单独核对目标与回滚条件。
