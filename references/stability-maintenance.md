# OpenClash / AdGuard 稳定性检查与维护

本文为通用排障经验，不包含真实设备配置、地址、节点、凭据或日志。只读确认实际状态后再应用；任何计划调整均需结合使用者可接受的维护窗口。

## 先确认谁在管理 AdGuard

大小写不同的 init 服务可能同时存在，甚至指向同一配置与工作目录。以进程启动参数、UCI 与 procd 状态确认活动实例，不按服务名或默认 YAML 文件名推断。数据库打开超时可能与重复进程争用有关，不能仅凭这一条日志判定原因。

确认重复入口未承载业务后，先备份，再停用重复入口，保留主管理服务与数据库。不要删除数据库，不要按程序名批量杀进程。检查当前进程是否保持运行、重复入口是否关闭，并核对开机启动状态。

## 固定重启与必要重启分开管理

稳定性不应仅靠固定周期重启维持。若决定取消，需同时修改持久设置和对应 cron 行，保留使用者需要的订阅更新与故障守护。取消固定重启并不阻止配置或规则库更新触发的必要重启。

## 检查规则库更新计划是否完整

更新开关打开，不等于任务有效。核对原生设置、生成任务和实际更新时间，确保 cron 有完整的分钟、小时、日、月、星期五个字段。

部分 OpenClash 版本使用下列选项：

| 类别 | 小时选项 | 星期选项 |
|---|---|---|
| Country/IPDB | geo_update_day_time | geo_update_week_time |
| GeoSite | geosite_update_day_time | geosite_update_week_time |
| GeoIP | geoip_update_day_time | geoip_update_week_time |
| ASN | geoasn_update_day_time | geoasn_update_week_time |

先核对本机源码或界面确认字段语义。示例维护窗口为每周日 04:00，即小时 4、星期 0；这只是示例，不能未经确认套用。仅修 cron 而不补齐原生选项，可能在下次生成计划时复发。

优先复用原生更新器，不另建未经验证的下载任务。核对更新器是否在数据变化时重启核心；配置计划不等于验证下载成功，也不等于验证新数据库可用。

## 保留明确的使用者取舍

- 固定出口或固定地区的手动组有合理用途，不应默认改成自动选择或故障转移。手动选择节点本身不保证供应商出口永不变化。
- 公共备用 DNS 可在主上游失败时提供部分解析能力，但可能绕过代理 DNS 策略；需明确取舍。
- Fake-IP 仅说明 DNS 行为，不证明实际连接经过代理或游戏连接正常。

## 最小变更验证

备份持久设置及计划任务，保留权限受限的回滚入口。只改获准字段，复核差异，检查代理源配置、运行配置和 AdGuard 配置是否被意外改变。仅调整计划时不必重启核心。

验证服务状态、重复实例状态、代表性 DNS、国内 HTTPS 和带现有认证的本地代理 HTTPS。代理返回 407 表示需要认证，不能直接认定线路故障。区分历史错误与本次变更后的新错误。

记录已验证与未验证事项：短时请求成功不能替代整机重启、定时更新执行、故障切换、实际游戏和长期稳定性验证。回滚旧配置前先检查后续变更，避免覆盖较新的设置。
